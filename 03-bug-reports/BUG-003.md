# BUG-003 — Checking out again after an order creates a second, empty order

**Reported by:** Carina
**Date:** 2026-10-20
**Component:** Checkout — POST /rest/basket/&lt;basketId&gt;/checkout
**Environment:** OWASP Juice Shop 20.2.0 (Docker image bkimminich/juice-shop),
http://localhost:3000, Chrome; also reproduced at the API level
**Severity:** Major
**Priority:** High

## Preconditions
- Logged in with a fresh account that has a saved address and card.
- Basket contains 1 × Apple Juice (1000ml).

## Steps to reproduce (browser)
1. Click the basket, then **Checkout**. Choose the address, delivery method
   and card, and continue to the Order Summary.
2. Click **Place your order and pay**. The order confirmation page opens and
   the basket is now empty.
3. Press the browser **Back** button until the Order Summary page is shown
   again. It now shows a total of 0.00 because the basket is empty.
4. Click **Place your order and pay** again.
5. Open **Order History** from the account menu.

## Expected result
Step 4 is refused because the basket is empty: the button is disabled, or the
server rejects the checkout with an error. Order History shows one order.

## Actual result
- Order History shows **two orders**. The second contains **no products** and
  has a total of **0.00**.
- Network tab, second `checkout` request: status **____** (fill in)

## Reproducibility
- Browser: 1 of 1 attempts.
- API: 1 of 1. Sending the same `POST /rest/basket/<bid>/checkout` again
  with the delivery method included returned **HTTP 200** and created an empty
  order with totalPrice **0.99** — the delivery fee charged for nothing.

## Notes / impact
Any double submission (Back + resubmit, double-click, network retry) creates
an extra, empty order. Through the API the empty order is also charged the
delivery fee. Related: BUG-002 — both come from the server not checking the
basket/order state before accepting a checkout.

**Oracle:** Purpose (an order must contain something to deliver) and User
expectations (no one expects an empty order, let alone to pay for one).
