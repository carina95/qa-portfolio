# BUG-004 — Address "Name" accepts a name made only of spaces, and never trims spaces

**Reported by:** Carina
**Date:** 2026-11-10
**Component:** Add New Address form (Basket → Checkout → Add New Address) — POST /api/Addresss
**Environment:** OWASP Juice Shop 20.2.0 (Docker), http://localhost:3000, Chrome
**Severity:** Minor
**Priority:** Medium

## Preconditions
- Logged in; basket contains at least one product.
- On the Add New Address form.

## Steps to reproduce
1. Fill in Country `Romania`, Mobile Number `7000000000`, ZIP Code `10001`,
   Address `1 Test Street`, City `Bucharest`.
2. In Name, type three spaces and nothing else.
3. Open DevTools → Network, clear it, then click Submit.
4. Look at the new address in the address list, and at the POST Addresss request.

## Expected result
The form treats a spaces-only name the same as an empty one: Submit stays disabled
and the "name required" message is shown. Names are saved without leading or
trailing spaces.

## Actual result
- Submit becomes clickable. POST Addresss returns **201 Created** with
  `fullName: " "`, and the address appears in the list with an empty-looking name.
- Leading and trailing spaces are never removed: ` Ana Pop` is saved as
  `" Ana Pop"`, and `Ana Pop ` as `"Ana Pop "` (Payload and response match).

## Reproducibility
Spaces-only name: 2 of 2 attempts.

## Notes / impact
The empty-name check doesn't trim whitespace, so "   " counts as a name.
A delivery address can be saved with no usable recipient name. Stray spaces
in real names can also cause mismatches when names are searched or compared.

**Oracle:** Product (empty names are already rejected; spaces-only should be too)
and Purpose (a delivery address needs a recipient name).
