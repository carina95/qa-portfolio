# BUG-001 — Registration password field states two different maximum lengths

**Reported by:** Carina
**Date:** 2026-09-11
**Component:** User Registration form (/#/register), Password field
**Environment:** OWASP Juice Shop 20.2.0 (Docker image bkimminich/juice-shop),
http://localhost:3000, macOS 26.6.2, Chrome 152.0.7977.83
**Severity:** Minor
**Priority:** Medium

## Preconditions
- Juice Shop running on http://localhost:3000, freshly restarted.
- No user logged in.

## Steps to reproduce
1. Open http://localhost:3000/#/register in Chrome.
2. Look at the Password field's hint text and its character counter.
3. Click into the Password field and type 30 characters, then continue past 40.

## Expected result
The field states one consistent maximum length. The hint text and the
character counter agree.

## Actual result
The counter reads "/20". Typing 30 characters — a valid length, since the 
real maximum is 40 — makes the counter show "30/20" in red, as if the
password were too long, even though it is accepted normally. The only
fault is the counter's maximum: it displays 20 where the field's true
limit is 40. The hint and the validation error both correctly use 40.

## Reproducibility
3 of 3 attempts, including on a freshly restarted container.

## Evidence
![Password field showing hint "5-40" but counter "/20"] (evidence/BUG-001-password-field.png)

## Notes / impact
The real maximum is 40 — stated by the hint and enforced by the validation
error that appears above 40 characters. The counter's "20" is never an
enforced limit anywhere; it only controls what the counter displays. A
user who types a valid password of 21–40 characters sees the counter turn
red (e.g. "30/20"), which looks like an error at a length that is actually
fine. Minor, but visible at the point of account creation, where users
are already cautious.
